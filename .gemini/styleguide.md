# Gemini Code Assist 리뷰 가이드

이 문서는 Gemini Code Assist가 본 저장소의 PR을 리뷰할 때 따라야 할 규칙을 정의합니다.
공식 문서: https://developers.google.com/gemini-code-assist/docs/customize-repo-review

## 언어

- PR 요약(summary), 코드 리뷰 코멘트, 변경 제안(suggestion) 등 **모든 출력은 반드시 한국어로 작성**합니다.
- 코드 식별자, 함수/변수명, 라이브러리/패키지명, 셸 명령, 에러 메시지 원문은 번역하지 않고 원문 그대로 둡니다.
- 인용한 영문 문서를 가리킬 때는 링크와 함께 한국어 한 줄 요약을 덧붙입니다.

## 톤

- 존댓말("~합니다", "~하는 편이 좋습니다")을 사용합니다.
- 단정적인 사실은 단정적으로, 추정은 "~로 보입니다", "~일 수 있습니다"로 구분합니다.
- 같은 지적을 반복하지 않고, 동일 패턴은 대표 위치 1곳에서만 코멘트합니다.

## 리뷰 우선순위

다음 순서로 비중을 둡니다. 위쪽일수록 강하게 지적해 주세요.

1. **보안**: 비밀 키/토큰 노출, SQL/명령 주입, XSS, 인증/인가 우회, CORS·헤더 누락.
2. **정합성**: 타입 오류, 런타임 예외, null/undefined 처리 누락, 비동기 경합, 잘못된 API 응답 처리.
3. **데이터 무결성**: 정답·해설 등 민감 데이터가 의도와 다르게 클라이언트로 흘러가는 경우.
4. **성능**: 불필요한 리렌더, N+1 쿼리, 대형 번들/이미지 로딩, 캐시 누락.
5. **가독성/구조**: 단일 출처(SoT) 위반, 책임이 모호한 모듈 분리, 명명 일관성.

스타일/포매팅은 Biome가 잡으므로 **중복 지적하지 않습니다**.

## 프로젝트 컨벤션

- 본 저장소의 Next.js는 최신 버전을 사용합니다. 학습 데이터에 있는 구버전 API(예: pages 라우터 한정 동작, 구 `getServerSideProps` 가정 등)를 기준으로 한 지적은 피하고, 필요하면 `node_modules/next/dist/docs/` 의 가이드를 인용해 주세요. (`AGENTS.md` 참고)
- **정답과 해설은 서버사이드에서만 노출**되어야 합니다. 클라이언트에 내려가는 라운드/공유 데이터에 정답이 섞이는 변경이면 **HIGH severity로 강하게 경고**해 주세요. (`README.md`의 "서버사이드 채점" 원칙)
- `lib/levels.ts` 와 같이 "단일 출처(Single Source of Truth)"로 명시된 파일은 다른 곳에 같은 정의가 중복되지 않는지 확인합니다.
- 환경변수는 서버 전용 키(`SUPABASE_SECRET_KEY`, `ANTHROPIC_API_KEY` 등)가 클라이언트 번들로 노출되지 않는지 확인합니다.
- 패키지 매니저는 **pnpm**입니다. `npm`/`yarn` 사용을 권유하지 않습니다.

## PR 제목과 본문

- 제목은 Conventional Commits 형식을 따릅니다 (예: `feat: 라운드 공유 OG 이미지 추가`, `fix: 채점 응답 타입 보정`).
- 제목과 본문 모두 **한국어**로 작성합니다.
- 요약(summary)은 "무엇을/왜" 위주로 3~6줄, 변경 파일이 많을 때는 영역별로 묶어 bullet로 정리합니다.
